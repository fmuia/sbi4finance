Heston learned summaries: complete fixed-grid comparisons

Development evidence only. Final epoch 300 is primary. The minimum native validation-loss checkpoint is secondary and is shown separately; it was not selected by posterior diagnostics. These results reuse historical development cases, retain every raw draw and do not establish fresh acceptance or a sufficient statistic.

All fits use 300,000 stored noisy data sets, 63 actual contracts, the same frozen ZCA transform, broad physical priors and inferred Gaussian noise multiplier c. A learned MLP summary layer is added before the same FlowMatching posterior head. The MLP fits use the same declared seed; changing the architecture changes weight shapes and random-number use, so a one-seed screen cannot separate representation effects from optimization variability. The screen order is 32, 16, 8, 4, then 64 dimensions. Only completed endpoints appear below; stopped partial fits are excluded. Mask-aware and moving-grid estimators are not trained by this comparison.

Limits and provenance

One seed per bottleneck size is an initial screen. Different dimensions and their checkpoint outcomes must all be retained. A smaller summary matching an imperfect baseline does not prove sufficiency. Full-grid MLP summaries do not establish support for masks, token permutations or moved contracts.

This self-contained report was rendered only from compact aggregate records. No model, clean price, individual parameter draw, raw observation or machine path is included. Payload hashes identify the private sources; no pricing, posterior sampling or reference sampling occurred during reporting.
