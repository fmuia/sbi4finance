# Paired larger-bank Heston training

**Development comparison with an audited numerical repair, 10 November 2026.** The user authorized a larger bank, two batch sizes and longer training. The original [protocol](protocol.json) binds the exact source checkpoint, existing bank, executable sources, training budgets and evaluation population. Both original runs stopped on the same valid generated target during pass81, before the corresponding optimizer update. Their artifacts and completed25-pass evaluations remain immutable.

The [precision failure audit](precision-failure-audit.json) identifies c=1.9999999587495068: its normalized bounded coordinate rounds to1 when the backend logarithm casts tofloat32, yielding an infinite target logit. All model/Adam state arrays remain finite. This is a target-preprocessing failure, not evidence that either batch size destabilizes the optimizer. The correct forward transform is computed as `log(x-lower)-log(upper-x)` in NumPyfloat64, followed by a float32 cast. The algebraically equivalent transform preserves the prior, quotes and inverse sampling, without clipping or redrawing c. It also improves ordinary finite roundoff, so a replay is not claimed to reproduce the old optimizer trajectory bit for bit.

The corrected [replay protocol](precision-replay/protocol.json) starts both branches again from the same60k parent with the same bank, paired raw examples, architecture, batch sizes, schedule and500-pass budget. Its new producer, checkpoint and output identities retain the original failures. The original absolute campaign deadline,19:48:49.590152UTC, remains in force; failed-run time is charged rather than resetting the overall wall clock. Original25-pass c intervals remain approximately prior-wide and are reported separately from the corrected replay.

The initial separate25-pass evaluator also required [read-only CLI schedule compatibility](evaluation-compatibility-v1.json): Keras's module metadata differed between a CLI-defined class and an imported class. The compatibility proof preserves the exact registered class, executable code, schedule rates, every saved array and every original loader check. The corrected producer imports its schedule class consistently and needs no such workaround. No posterior sampling preceded the initial failed evaluation startup.

Both branches restore every saved model, Adam, normalization and auxiliary state array from the same six-target update-060000 checkpoint. They use all100,000 physical training surfaces from the preserved bank, without repricing. Each physical row receives one fresh c~Uniform(.5,2) and54 independent Gaussian errors per pass, under a new augmentation namespace. Shared row permutations and paired noise/scale draws make the example stream identical across branches, regrouped into batches. The model remains `Y_i=P_i(phi)+c*h_i*Z_i`; c is a target only, never an input. Geometry, physical priors, spreads, architecture and effective zero dropout remain unchanged.
