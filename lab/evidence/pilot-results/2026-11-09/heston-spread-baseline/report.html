What does “conditional result” mean?

Conditional means conditional on this one observed set of quotes. Hold all 54 quotes fixed and ask whether the fast network reproduces the posterior from our chosen Heston model. MCMC supplies a reference for that same dataset.

One fixed set of 54 option quotes
    ├─ Network → fast posterior draws for five Heston parameters
    └─ MCMC    → reference posterior draws for those same parameters
                    ↓
          Compare posterior means and 90% interval widths

For one fixed set of 54 quotes, compare the network’s draws with MCMC under the same prior, pricing model and Gaussian likelihood. These checks assess the network’s approximation to that posterior. They do not require its mean to equal a generating truth and do not establish that Heston describes actual market prices.

Mean error = |network mean − reference mean| / reference SD ≤ 0.30
Width ratio = network central-90% width / reference central-90% width ∈ [0.75, 1.25]

A pass places the sampling-uncertainty interval wholly inside the allowed range; a fail places it wholly outside; an inconclusive result overlaps a boundary. The evaluator accounts for correlated reference draws and finite neural draws, using approximate family-adjusted uncertainty intervals and two reference block lengths. A combined quantity passes only when both mean and width pass.

Exactly how one case receives its label

The network has five parameter targets. We also calculate two variance quantities from the same paired draws. That gives seven quantities × two checks = 14 checks per quote surface. Any definite failure makes that case fail; all 14 must pass for the case to pass; otherwise it is inconclusive. “Fail” does not mean every parameter is wrong. An unavailable reference also makes a case inconclusive.

For example, market-like κ and θ pass both checks, and the later-window expected variance passes too. The case still fails because ξ’s mean misses by .57 reference SD and ρ’s interval is 54% too wide. The result describes those specific disagreements, not a completely unsuccessful inverse fit.

Why SBC and the per-dataset failures can coexist

SBC averages over prior-generated datasets; biases can vary across datasets and a finite screen has limited power. It does not establish joint dependence or real-market validity. As a hypothetical illustration, returning the prior for every dataset can yield uniform SBC ranks while ignoring the observations. This is not a description of our fitted network; it shows why SBC alone cannot establish accurate use of the quotes.

SBC remains useful for detecting systematic rank distortion across many simulations without calculating an MCMC posterior for every dataset. The fixed-quote comparisons supply the complementary check of whether the network approximates the actual posterior on particular examples.

The same development pool has been reused across checkpoints and interventions. These plots help diagnose this development round; they are not fresh acceptance evidence for the chosen recipe.

Exactly which network, dropout and learning rates were used?

There are two fresh runs, not one run with dropout removed at 10k. Branch A stops at 10k. Branch B starts afresh with matched initialization, rows and noise streams, effective dropout zero, and is then continued. The 60k result belongs entirely to Branch B.

Actual construction code, extracted from the frozen trainer. The constructor visibly sets dropout=.05; the rest of the resolved defaults are listed in the table above.

def build_workflow(task, schedule_updates=10000):
    """Public BF2.1 spline workflow; no generating c or tau conditioning."""
    validate_task(task)
    import bayesflow as bf
    import keras
    if bf.__version__ != "2.1.0" or keras.backend.backend() != "jax":
        raise RuntimeError("use the locked BayesFlow 2.1.0 JAX core environment")
    adapter = bf.Adapter()
    names = task["target"]["parameter_names"]
    for name, (lo, hi) in zip(names, task["target"]["prior_bounds"], strict=True):
        adapter = adapter.constrain(name, lower=float(lo), upper=float(hi), inclusive="none")
    adapter = (adapter.convert_dtype("float64", "float32")
               .concatenate(names, into="inference_variables")
               .concatenate(["observations"], into="inference_conditions"))
    optimizer = keras.optimizers.Adam(keras.optimizers.schedules.CosineDecay(
        initial_learning_rate=5e-4, decay_steps=schedule_updates, alpha=.1))
    flow = bf.networks.CouplingFlow(transform="spline", subnet_kwargs={"widths": [128, 128], "dropout": .05})
    workflow = bf.BasicWorkflow(adapter=adapter, inference_network=flow,
                               standardize=["inference_variables", "inference_conditions"], optimizer=optimizer)
    workflow.estimator.compile(optimizer=optimizer, steps_per_execution=1)
    return workflow

Why was dropout present?

The spline pilot explicitly carried over the .05 coupling-MLP default. There was no financial reason to require dropout. During training, it sets each hidden activation to zero with probability 5% and scales retained activations by 1/.95. This is neural regularization; it does not remove quotes, add price noise or infer market uncertainty.

Validation and posterior inference disable dropout. We did not use Monte Carlo dropout. The original FlowMatching builder’s time-MLP default was dropout 0.0, so using .05 here was another change from that recipe. It should have been explicit in the comparison from the beginning.

The matched zero-dropout control first constructs/builds the original .05 model, then changes the existing 24 rates to zero before its fresh training run. The switch is checked to leave all initialized arrays unchanged, and the original saved deterministic initial probes match. The original run did not save its full initial array archive, so a direct archive-to-archive initial-state comparison is unavailable. Directly constructing a new network with dropout=0 is not claimed to be an exact replay of this control.

The saved archives retain the original .05 constructor configuration. The strict checkpoint loader reapplies the recorded effective zero rates and verifies saved state and seeded inference. This explains why inspecting a constructor field alone can show .05 even for the zero-dropout control.

Actual zero-dropout switch and its state checks
def switch_dropout_zero(model, *, reloading=False):
    """Change only existing Dropout rates after original .05 initialization."""
    layers = dropout_layers(model)
    rates = [float(layer.rate) for layer in layers]
    if len(layers) != 24 or any(rate not in ((0., .05) if reloading else (.05,)) for rate in rates):
        raise ValueError("zero-dropout control requires the frozen 24-layer .05 construction")
    before = state_summary(model, current_state(model))
    for layer in layers:
        layer.rate = 0.
    after = state_summary(model, current_state(model))
    if before != after:
        raise RuntimeError("changing dropout rates changed learned/permutation/optimizer/standardizer/RNG arrays")
    return {"method": "construct/build original .05 model, then change existing Dropout.rate to0 before the first update",
            "rates_before": rates, "rates_after": [float(layer.rate) for layer in layers],
            "array_state_unchanged": True,
            "state_groups": {name: {"variable_count": len(rows), "before_sha256": fingerprint(rows),
                                    "after_sha256": fingerprint(after[name])} for name, rows in before.items()},
            "original_initial_full_hash_available": False,

With less observation error, informative quotes can produce a much sharper posterior. What is volatility of volatility—and is 1.5 unreasonable?

Heston models instantaneous variance V, with instantaneous volatility √V. The parameter convention used here is:

dV = κ(θ − V) dt + ξ √V dW
Time is measured in years; variance and volatility use decimal annualized units. ξ controls random fluctuations of variance and is commonly called volatility of volatility.

There is a real economic counterpart: volatility fluctuates, and volatility derivatives carry information about those fluctuations. Heston’s ξ is nevertheless a model parameter inferred from prices. It is not a directly observed index value.

A local interpretation follows by applying Itô’s rule to σ=√V at V>0. The diffusion term of dσ is (ξ/2)dW. Over a short business-day increment, its local shock scale is approximately ξ/(2√252), in decimal annualized volatility:

This is a local diffusion scale derived from the model, not a finite-day forecast, confidence interval or empirical estimate. Drift, mean reversion and boundary behavior matter, especially at large ξ and small V. For example, a 4.72-point change takes 20% annualized volatility to roughly 24.72% in this local illustration.

There is no universal mathematical ceiling at 1.5. It implies substantial volatility fluctuation under this convention and needs justification in a particular market/task. A posterior pushing above 1.5 is evidence about the model fit under its assumptions, not proof that actual volatility follows Heston with that ξ. In an option calibration we infer a pricing-measure model; interpreting ξ as a directly measured historical volatility statistic requires additional assumptions.

A familiar market analogue is Cboe’s VVIX, derived from VIX options and describing expected volatility of the 30-day forward price of VIX. It is related to volatility-of-volatility risk, but cannot be read off as Heston ξ: the underlying quantity, units and horizon differ.

For mathematical context, the sufficient strict-positivity condition is 2κθ ≥ ξ². Violating it does not make the usual nonnegative Heston variance process invalid; zero becomes attainable. It can matter for numerical schemes. The condition depends on κ and θ together with ξ, so it cannot justify a universal ξ cutoff. See Janek, Kluge, Weron and Wystup, §1.3.3. This report does not establish a typical empirical SPX range for ξ.

What widening ξ established

The old 1.5 ceiling materially constrained that earlier market fit. It did not establish a universally appropriate ξ range, resolve market residual structure, or make a wider-prior neural task comparable with the original example. The earlier spread-only market fit still had RMS residual about 12.3 half-spreads; a higher fitted ξ can be a model's attempt to explain a surface it does not adequately describe. These extra choices should have been highlighted and isolated before interpreting the regression.

A cleaner next comparison

The immediate question should be whether lower noise alone strains the original amortized example. It requires a matched control, rather than another mixed redesign.

  1. Retain the original task and training recipe. Four targets, κ=2, ξ≤1.5, canonical 63-contract geometry, original FlowMatching family, and matched distinct-surface and update budgets.
  2. Vary only a known synthetic noise amplitude. Compare σ=a×σold at a small predeclared set of amplitudes, with separately matched likelihoods and networks. Use a for this synthetic multiplier and retain c for the market-spread model c×h. This tests shrinking noise; it does not claim to reproduce a market spread profile.
  3. Check pricing precision before bank reuse. Tighter noise tightens the numerical requirement. Retain compatible clean labels only where refinement supports them; do not assume zero repricing.
  4. Then introduce market geometry/profile and physical-prior changes separately. A 54-contract, κ=2, ξ≤1.5 control can test the actual-quote setup without the broader dynamics. It needs matching pricing labels: existing free-κ prices cannot simply be relabelled as κ=2.

This is a proposed attribution experiment, not a newly executed fit. The current 60k results remain useful engineering evidence under their own task identity. No training, sampler escalation or Bergomi production was launched to create this report.
