# Manifest

What `tutorial/assets/` holds and where each file came from. The notebooks read these files and nothing else
in the repository, and the tutorial's tests check every file against the SHA-256 recorded below. Paths are
relative to `tutorial/assets/`.

## How a file enters `tutorial/assets/`

Every file is written by a lab tool, never by hand:

| Folder | What | Written by |
|---|---|---|
| `results/calibration/` | Accepted study results (S1 to S9) | `lab/studies/accept.py`, which adds `ACCEPTED.json`: the source run, the SHA-256 of every source file and every change made |
| `checkpoints/` | Trained networks | `lab/studies/accept.py`, with the optimizer state removed and same-seed draws checked identical |
| `data/` | The exact Heston posterior on SPY (a feasibility run, not an accepted study) | `lab/checks/heston_spy_exact.py` |
| `quick-checks/`, `images/` | Outputs of the lab's quick checks and two figures | `lab/studies/manifest.py`, as copies of the files named in the last column of the table |

Every result JSON records the task fingerprint, the bank manifest's SHA-256 and, where a network was used, the
checkpoint's SHA-256, so each file can be traced to its inputs. The banks themselves are not copied: each is
regenerated exactly from its configuration file and seed.

## The code behind the results

The studies ran on the lab's library, `lab/src/sbi4finance/calibration/`, with the simulators it imports
(`rough_bergomi.py`, `bergomi.py`, `hkde.py`). The notebooks do not import it: the parts they compute live
(Black–Scholes and implied volatility, the Heston Fourier pricer, one rough-Bergomi smile, the network's adapter
and sampler) are copied in `tutorial/src/sbi4f_tutorial/`, and the lab's tests check that the copies return the
same numbers (`lab/tests/test_tutorial_parity.py`).
